# ログインとレーティングの有効化

参考: [lit-kei/mathProblems](https://github.com/lit-kei/mathProblems)。同じ入力方式を採用し、現在の `sankakufunction` プロジェクトで独立したアカウントを作成します。参考サイトのアカウントや個人情報は移行・共有しません。

## ログイン方式

- 校内用: 半角7桁の生徒番号を `番号@school.local` に変換して Firebase Email/Password 認証します。登録時に学年（1〜3）、クラス（1〜7）、出席番号（1〜41）を入力します。先頭のゼロは保持します。
- 一般用: メールアドレスとパスワードで登録・ログインします。一般用メールの `school.local` ドメインは受け付けません。
- ユーザー名は半角英数字・`-`・`_` の3〜10文字。大小文字を区別せず一意です。初期パスワードは8文字以上。パスワードは Firebase Authentication のみに送信し、Database・localStorage・ログには保存しません。
- ログイン状態は Firebase のブラウザー永続化で維持します。ロビーからの退出でログアウトしません。同じアカウントでのロビー同時参加は防ぎます。
- 生徒番号・学年・クラス・出席番号は `privateProfiles/{uid}` に保存し、本人のみ読み取れます。公開プロフィールはユーザー名・区分・登録時刻・校内確認フラグのみです。
- 校内所属は参考サイトと同様に**自己申告**です。7桁の番号だけで在籍確認はできません。`schoolVerified` の初期値は false で、一般ユーザーは変更できません。厳密な校内限定運用には別途管理者による在籍確認が必要です。
- 一般用はメールでパスワード再設定できます。`school.local` は実際のメールアドレスではないため、校内用の再発行は管理者が Firebase Console などで対応します。

## 本番設定

1. Firebase Authentication → Sign-in method で **メール／パスワード** を有効にします。ゲスト対戦用の **匿名** も引き続き有効にしてください。
2. Firebase Console で Cloud Functions が使える **Blaze プラン**になっていることを確認します。未設定の場合は、料金を確認してから管理者が変更してください。この実装は請求プランを変更しません。
3. 管理者の手元で Node.js 22 と Firebase CLI を用意し、対象プロジェクトにアクセスできる Google アカウントでログインします。

```sh
firebase login
cd sankakuFunction
npm ci --prefix functions
firebase deploy --only functions:trig-battle,database --project sankakufunction
```

`firebase.json` の predeploy で共有コードを `functions/shared` にコピーし、サーバーコードを確認します。`functions/shared` は生成物です。レーティング関連のソースファイルを変更したら、Functions も再配置してください。手動配置時にこのフォルダーをコピーし忘れないよう、上記の Firebase CLI のコマンドを使ってください。

Database のデプロイはルールを置き換えます。既存の独自ルールがある場合は、先に `firebase/database.rules.json` に統合してください。Database のユーザーデータは削除しません。

配置する関数:

- `registerProfile`: ログイン済みの本人の識別子を検証してプロフィール、非公開の校内情報、初期レート、ユーザー名の確保を一括作成。
- `settleMatch`: RTDB の試合更新を受け、最新の対戦データから結果と双方のレートを一つのトランザクションで確定。

関数の地域は、指定済みの米国 Realtime Database に合わせて `us-central1`。各関数は最大3インスタンスです。Cloud Functions の管理画面でログ・実行回数・課金を確認してください。

4. GitHub Pages の公開が完了したら `account.html` で校内用／一般用の登録を確認し、別端末の登録済みアカウント同士で対戦します。`rankings.html` で戦績とレートが反映されることを確認します。

Functions 未配置で登録が失敗した場合、Firebase Authentication のユーザーだけが作られていることがあります。再登録するのではなく、そのアカウントでログインし、表示されるフォームからプロフィール登録を完了してください。

## レートの仕様

初期値1500、Elo の K=32。期待勝率 `1 / (1 + 10^((相手レート − 自分レート) / 400))`、実際の得点は勝ち1・引き分け0.5・負け0。変化量は整数に丸め、両者の合計レートを維持します。同格の相手への勝利は +16、敗北は −16。

- ログイン済みの両者が登録を完了しており、申請側がレーティング対戦を希望した試合を対象にします。
- ゲスト、ローカルのお試し、フレンドリー対戦はレート対象外。
- 開始前の終了はレートを変更しません。カウントダウン終了後の降参は敗北です。
- 10問目の正解が到着した後の降参で、確定済みの勝者は変わりません。
- 同じ2アカウント間のレーティング反映は、日本時間の同じ日につき5試合までです。5試合目と上限到達後の結果画面でだけ案内し、6試合目以降は対戦できてもレート・戦績を変更しません。
- 登録時の初期化や対戦結果の再通知によって、既存レートを初期化したり二重加算したりしません。
- レート・試合確定結果・プロフィールはクライアントから書き込めません。Admin SDK だけが更新します。試合確定後は回答・取消の追加も禁止します。
- ランキングは1試合以上のレート対象の対戦を行ったプレイヤーを表示し、全体／校内用／一般用で絞り込めます。学生情報をランキングに載せません。

問題の正答は学習用クライアントから確認できるため、これはカジュアルな学習レーティングです。賞品のある競技などの厳密な不正対策は別の運用が必要です。

## 検証

```sh
npm test
node scripts/prepare-functions.js
npm --prefix functions run check
```

Firebase の本番ログイン・関数実行・ルールは、実際の配置後に別途確認してください。ユニットテストやモック認証の画面テストは、本番の Google 認証や Functions 配置の成功を証明しません。

## 運用上の制限

現段階の集計は整合性を優先して `trigBattle` 配下のトランザクションを使用します。校内規模の少人数向けです。人数が増えた場合は、試合確定とレート処理をキューなどで分割し、古い試合の定期削除とランキングのページングを追加してください。個人情報の削除時は管理者が Authentication と `privateProfiles` を合わせて整理してください。
